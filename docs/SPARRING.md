# 人族战术陪练初版

本次实现两个固定规则对手，供 dayuan 练习完整对局。当前仅支持 LR，100% 速度，一次启动一局，不自动续局。保留 P0 OB 槽，dayuan 为 P1 亡灵，人族 bot 为 P2。两方分别使用 `Game(player=1/2, fair=True)`，串行下令，观战视野不交给策略。

这是离线验证通过的首版，尚未启动实机验收。场景加载、运行时识别 P0 原生 observer、双 bot 的持续运营和完整胜负均待验证；配置不符会拒绝继续，而不会降级到让用户控制其中一方。后台持续运行暂不支持：失焦时保留暂停等待，不把 Python 后台进程当作魔兽游戏仍在推进。

## 两种战术

| 对手 | 开局与后续 | 受扰后的处理 |
| --- | --- | --- |
| `human-fast-expand` | 大法师、四步兵，侦察并清理附近可达分矿；可见且无守卫/敌人时建二矿；二矿实际完成前不升本；随后补塔、火枪及二本 | 补工人、续建、祭坛重建和英雄复活；同一分矿连续三次建造失败后转单矿发展，日志明确记录放弃 |
| `human-rifle` | 大法师、两步兵，铁匠铺、火枪；三火枪后补第二兵营，四火枪后留钱升二本，六火枪成军出门 | 家中遇敌先防守；补工人、续建和关键建筑重建；残血单位撤回，英雄死亡后复活 |

共用能力包括矿工分配、伐木、补人口、施工工人保留、资源不足时存钱、基础练级、可见目标集火、大法师水元素、残血撤退及出生点搜索。建造接受回执和地基出现分别记录，二矿完成以观测为准。工人一次离开快照不视为死亡。

限制：它们仍是简单规则对手，没有完整的民兵速矿、商店补给、精准拉野、复杂阵容转型或成熟人族团战微操。关键建筑连续三次选址失败会停止该位置重试并记录，仍可能需要实战改进。不能据离线测试声称具备人类战术水平或已有稳定胜率。

## 启动

先按仓库原有方式配置固定上游 SDK、游戏和地图绑定。人机练习使用的两个窗口辅助来自固定 fork；若该目录不存在，需要克隆后检出准确版本：

```powershell
git clone --no-checkout https://github.com/miaolinvip/OpenWar3AI.git artifacts/human-vs-ai-source-20261028
git -C artifacts/human-vs-ai-source-20261028 checkout --detach 68c40c0d0f2149f44584195a7cdb91ba975bf90e
```

只生成、检查场景，不启动游戏：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B bot.py sparring --opponent human-rifle --check
```

显式启动一局，有完整 OB 槽：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B bot.py sparring --opponent human-fast-expand
.\.venv\Scripts\python.exe -X utf8 -B bot.py sparring --opponent human-rifle
```

两条是不同选择，不要同时执行。已有游戏会阻止新启动。可显式加 `--minutes 5` 做有时限诊断；默认没有对局时限。`bot.py stop` 请求结束并清理这次自有游戏，不自动开下一局。

原图保持不变；生成的观战副本在 `artifacts/sparring-maps`。仅修改地图脚本的玩家配置、初始化和大厅元数据，保留地形、单位数据、野怪及掉落函数。P0 无部队，只向 P0 开全图视野；P1/P2 不共享视野或控制。此场景不运行原生 AI 或原图近战胜负触发器，由现有 referee 以一方建筑全部消失判定终局，因此不宣称与正式天梯所有规则完全等同。

每局沿用源码冻结和 `events.jsonl/result.json`；增加带对手名称、玩家号的 `human_*` 事件、战术阶段、二矿进度、生产和资源摘要。原始全图仅供初始化验证及胜负裁判，策略读取各自公平视图。
