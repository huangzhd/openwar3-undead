## 按订单复核

使用原始文件生成待审清单。每项保留时间、坐标、命令块、子组选取线索和本窗口解码缺口。相同建筑曾在相同点下令、相邻同类订单换点、前序子组非侍僧均只作复核提示。连续两座通灵塔可能本来就要造在不同位置，不能直接判为误操作。

```powershell
node tools/replay-intake/intake.cjs match.w3g --source source.json --opening-player 1 --opening-review --out review.json
node tools/replay-intake/intake.cjs match.w3g --source source.json --opening-player 1 --opening-review --review-notes notes.json --out annotated.json
```

笔记格式为 JSON 数组，每项包含原清单的 `id`、`verdict`、非空 `comment`。可标为战术待复核 `tactical_review_candidate`、疑似重发或修正 `possible_reissue_or_correction`、无法判断 `undetermined`。再次导入会重读原件，用录像哈希、来源、参赛槽和具体订单核对笔记；未匹配、重复或试图添加批准字段的笔记整份拒绝。公开格式样本禁止标为战术候选。已登记的公开样本也按原件哈希识别，缺来源参数时仍保留格式样本分类。所有笔记均与训练标签隔离。[实样核验](evidence/replay-opening-review-20261103.json)

## 单个选手的开局订单
