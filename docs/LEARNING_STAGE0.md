## 观察与动作边界草案 v1

| 数据/操作 | 学习 actor 的边界 |
|---|---|
| 身份与时间 | 固定P1、已绑定的进程/epoch、当前游戏时间；跨局与旧观察拒绝使用。游戏时钟停止是接口健康问题，不累计决策时间。 |
| 己方状态 | 仅己方资源、己方单位/建筑/生产、可合法查询的技能与背包；未知值保留未知，不补0。 |
| 敌人与野怪 | 仅本帧P1公平可见实体；历史信息必须来自此前合法观察并带时间，失去视野不等于死亡。 |
| 地图 | 允许已登记的公共地形、营地与出生候选；不把真实敌方出生或隐藏位置作为先验输入。 |
| 输出动作 | 由现有P1玩家通道执行移动、攻击、施法、生产、建造、购物等；行动单位归属、句柄/epoch、目标可见性及前置条件必须在执行时复查。拒绝也要记录，不能静默改成另一动作。 |
| 动作证据 | 分开记录请求、接口接受、随后观察到的效果；接口接受不代表命中、治疗或生产完成。 |
| 终局 | 只由现有独立全灭建筑裁判提供自然胜负；停止、探针超时、接口错误分别归类，不伪造学习胜负。该裁判不是完整天梯规则。 |
| 旁路诊断 | P0全图、P2经济、KFAI内部策略、裁判原始全图状态、相机与速度操作均不进入actor输入；诊断文件不直接拼接成训练样本。 |

已核对固定SDK `game.py`：`_view`过滤单位/物品/生产表，却未过滤`players`资源表；`resources(player=N)`允许指定其他玩家。生产表也可能包含可见敌方建筑。`_remember`会在原始单位标为死亡时清除记忆，不能直接作为未来严格部分可观测记忆的依据。因此未来序列化器必须显式列出允许字段、仅取己方生产与资源，自行维护基于可见事件的记忆，并加隐藏资源/生产/死亡信息的负向测试。现有规则控制器未在本轮更改，不能由这些SDK接口的存在直接推断本局策略使用了隐藏信息。

AI在初次策略初始化、策略切换后及动态配兵决策后，将实际`strategy/chosen_strategy/chosen_counter`发布到现有AMAI缓存的独立命名空间。外部工具独立读取，写入本局`opponent-strategy.jsonl`；dayuan控制器不接收这些标签。编号来自原包人族13个策略定义，英雄首发并不能单独说明策略编号。

发布序号奇数表示写入中，偶数表示完成；读前后序号必须一致，最多两次读取尝试。未读到的序号明确记入`missed_publications`，日志时间是观察到标签的时间，不是内部切换的精确发生时间。启动后30游戏秒没有一致数据，或连续3次读取错误，停止该诊断并保留失败记录，不把未捕获写成通过。

本次仅完成离线测试和pjass编译。AI脚本与外部JASS通道是否共享该缓存，尚未实机证实；没有新局、没有策略切换实录，也不能回填125914局的策略标签。
