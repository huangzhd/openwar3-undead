# 阶段0规则基线接口 v1

2026-11-02新增独立、显式基础动作接口`dayuan-primitive-action-v1`（[LEARNING_ACTIONS](LEARNING_ACTIONS.md)），外部控制模式在新局契约记录policy/action_version；原规则基线和冻结历史版本不改。该入口只有离线验证，支持六种基础动作，不表示完整合法动作掩码、训练模型或学习actor已验收。

阶段1单实例接口与连续重置的新增契约见[LEARNING_ENVIRONMENT](LEARNING_ENVIRONMENT.md)。提前调用close使用`environment_close`归为user_abort，奖励null；不改变下方自然终局规则。

适用范围：LR、P0 空观战槽、P1 dayuan 亡灵、P2 KFAI 人族，单客户端机器人陪练。默认窗口1280×720、视距2500、400%速度。KFAI保留原AI，公平性标为`native_KFAI_unverified`，不宣称等同天梯。

## 固定版本与边界

| 项目 | 版本 | 契约 |
|---|---|---|
| 观察投影 | `strict-p1-observation-v1` | 仅己方资源、生产、背包/技能及己方和P1当前可见实体；未知保留null；可见历史独立维护，隐藏死亡不清除记忆。这个版本描述轨迹白名单，不表示SDK整个快照都可作为学习输入。 |
| 规则动作接口 | `rule-native-v1` | 现有P1玩家车道的原生移动、攻击、生产、建造、施法等接口。请求、接口回执、后续观察分开保存；接受不等于效果发生。不是高层学习执行器或完整合法动作掩码。 |
| 被动轨迹 | `dayuan-trajectory-v1` | 观察/点查询/请求/回执/终止分别记录；目标不可见、来源不合法或编码不完整时载荷省略，不伪造可重放动作。 |
| 终止语义 | `dayuan-outcome-v1` | 见下表；原始`result/reason`保留，净化后的`termination`与轨迹共用分类函数。 |
| 冻结契约 | `dayuan-interface-contract-v1` | 每局`interface-contract.json`记录源码清单摘要、地图哈希、策略/对手/接口版本、实际SDK Python/JSON、运行时Python、游戏数据JSON和二进制哈希；PID/epoch作为本局绑定单列。 |

P0全图、P2经济、KFAI内部策略、裁判全图状态及窗口/速度控制只用于隔离的诊断或裁判，不进入学习观察。P1点查询固定调用P1 native；失败、身份/epoch变化为未知，不回退P0。完整字段与被动动作限制见[轨迹契约](LEARNING_TRAJECTORY.md)。

## 终止分类

| 分类 | 条件 | 胜负奖励 |
|---|---|---|
| `natural_terminal` | 独立全灭建筑裁判确认，win/loss与对应原因完全匹配 | +1 / -1 |
| `user_abort` | STOP、手动重开、手动投降、环境提前close | null |
| `time_limit` | 游戏时限或墙钟截止 | null |
| `runtime_failure` | 接口/启动错误、阶段执行超时 | null |
| `process_exit` | 游戏进程退出 | null |
| `epoch_changed` | 会话或玩家身份变化 | null |
| `incomplete` | 其他未能确认的结果 | null |

只有自然终局`terminated=true`，其余均`truncated=true`。自然失败可以是规则基线的有效负样本，不能把断线/超时当作策略输棋。清理失败另记错误字段，原始胜负不改，但该局不能成为合格基线候选。裁判只实现全灭建筑判定，不覆盖完整天梯规则。

## 启动、后台与收尾

启动最多等待120墙钟秒，并受调用者墙钟截止约束。记录实际玩家、速度、兵种，核对地图、OB、敌对关系及共享权限，暂停P1原生AI后才进入规则控制器。逐native记录开始、结束和错误；不重试写动作，不绕过SDK多人保护。

机器人陪练允许在后台启动和运行，启动仍要求实际游戏时钟推进。运行时失焦不跳过P1/P2控制器、观察、裁判及回执；焦点变化单独记入日志。实际时钟未变化时不重复下令；后台时钟连续停滞15墙钟秒，或P1/观战必要快照持续缺失10墙钟秒，会明确失败并清理，不强行解除用户暂停。两种快照交替缺失不能重置超时；必须恢复完整有效视图。真人practice的失焦行为保持原约定。

限时或轨迹模式继续使用协作式`RunGuard`，记录阶段与慢调用；显式限时局单阶段预算2秒。此机制不能强制中断不返回的底层C调用。后台单实例通过不等于最小化、连续reset、多实例或长期无人值守已验收。

退出先解除计时包装，再关闭轨迹/查询/计数器/显示客户端和本局游戏；某个客户端关闭失败不能跳过游戏清理。`source-audit.json`分别比较冻结副本、工作区源码和依赖，并检查session关闭及实际游戏进程。缺证据、未知状态和哈希不一致不得记为通过。

## 验收与后续阶段

阶段0验收对象是明确版本的规则基线、接口边界和结果证据，不自动批准学习actor或训练数据集。不同源码、地图与速度独立归档，保留失败局。阶段1负责环境reset/observe/step/result/close、持续重置与实例隔离；阶段2负责完整学习动作、合法掩码、执行效果对齐及数据读取器。
